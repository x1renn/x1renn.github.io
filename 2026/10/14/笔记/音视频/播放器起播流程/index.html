从码流到画面的完整流程

以 BTV 的 H.264 / AVC + HTTP-FLV 线路为例：

  1. 打开输入、探测流信息：读取 FLV 中的配置记录，取得 SPS/PPS、编码类型、尺寸和时间基。
  2. 初始化解码器：把流参数交给解码上下文，选择软件解码或 D3D11 硬件解码。
  3. 持续读取视频包：视频包中的 NALU 按 AVCC 长度前缀排列，由 FFmpeg 完成解析。
  4. 建立解码参考状态：从直播中途接入时，需要取得有效参数和合适的随机接入点，H.264 常用 IDR。
  5. 解码、同步、显示：取得解码画面，根据时间戳安排呈现，再交给 Qt 渲染。

服务端缓存 Sequence Header + 最近一个可解码 GOP，可以让新观众更快取得参数和起始关键帧，从而缩短起播等待。

定位、参数变化与起播速度

定位与重新加载

本地 seek 成功后，项目依次处理：

  1. 清空音视频包队列。
  2. 通知音视频解码线程执行 flush。
  3. 重置同步时钟。
  4. 从定位后的数据继续解码，丢弃目标时间之前的画面。

时移回放切换也通过队列清理和解码状态刷新衔接时间线。重新加载输入时，则关闭旧会话并重新建立解码上下文。

推流参数变化

推流端更新 H.264 配置时，FFmpeg 可以通过包的 AV_PKT_DATA_NEW_EXTRADATA 传递新的配置记录，供解码器更新参数。

显示模块根据实际输出帧适配：

  • 从 AVFrame::width/height 获取当前尺寸。
  • 软件路径使用 sws_getCachedContext() 更新转换上下文。
  • 硬件路径根据 GPU 纹理尺寸和格式更新显示资源。

面试回答模板

项目的 AVC 线路使用 HTTP-FLV。我通过 FFmpeg 打开输入、探测流信息，取得包含 SPS/PPS 配置记录的流参数，再复制到解码上下文并打开解码器。

解封装线程持续读取压缩包，分发给音视频队列和缓存、录制旁路；视频线程使用 send/receive 接口解码，再根据时间戳同步并发布画面。AVCC 和 Annex-B 的解析由 FFmpeg 完成，应用使用统一接口。

正常起播由解码器建立参考状态；视频解码回退等恢复场景会等待关键包。seek 时清理队列、刷新解码状态并重置时钟。起播探测使用较小的 probesize 和 analyzeduration，播放积压通过队列和同步调度控制。

D3D11 硬解输出 GPU 表面，项目保留帧和设备引用，通过纹理采样或 GPU 内部 YUV 复制完成显示准备，最终由 shader 完成颜色转换。
