容器

QString

QString 是 Qt 的 Unicode 字符串类型，以 UTF-16 保存文字，并提供查找、截取、替换和编码转换等操作。

QString 与 std::string 的不同

存储编码、操作单位和配套功能。

对比 std::string QString
编码 本身不规定编码，常约定为 UTF-8 UTF-16
size() char 数量，存 UTF-8 时就是字节数 UTF-16 码元数
截取单位 char 字节 UTF-16 码元
文本工具 基本拼接、查找、截取等 另有 Unicode 大小写、字符分类、规范化和编码转换等
普通复制 建立独立字符存储 通常先共享存储，修改时分离
接口配合 标准 C++ 及许多第三方库 Qt 控件、QML、模型、网络等

Unicode 给字符规定编码标识；UTF-8、UTF-16 则规定这些字符怎样存成字节或码元。

隐式共享、写时复制与 STL 的区别

先共享，写入时再分离

QString、QByteArray、QList、QMap 等容器采用隐式共享，只传递指向数据的指针，并且只有当函数写入数据时才会复制数据，即写时复制。共享类由一个指向共享数据块的指针组成，该数据块包含引用计数和数据。

创建共享对象时，它会将引用计数设置为 1。每当有新对象引用共享数据时，引用计数就会递增；当对象取消引用共享数据时，引用计数就会递减。当引用计数变为零时，共享数据将被删除。在处理共享对象时，有两种复制对象的方式。我们通常称之为深拷贝和浅拷贝。深拷贝意味着复制一个对象。浅拷贝是引用拷贝，即仅指向共享数据块的指针。进行深拷贝在内存和 CPU 方面可能代价高昂。进行浅拷贝非常快，因为它只涉及设置指针和增加引用计数。

std::vector 的普通复制通常立即建立独立元素存储。Qt 将可能的大复制延后到需要写入的时候，因此第一次修改共享副本可能比预想的昂贵。

非 const 访问也可能触发分离

容器不知道你取得可写引用后是否真的会改，所以非 const 的 begin()、operator[] 等调用也可能触发分离。

仅把循环变量写成 const auto&，不保证容器使用 const begin()；std::as_const() 才是将访问对象变为 const。它声明在标准头文件 <utility> 中。

分离、扩容和修改可能使已有迭代器、引用或裸指针失效。不要拿着一个元素引用，再随意复制或修改相关容器。

复制容器，不等于复制指针指向的对象

这时通过 a 中的指针也能观察到名字变化。STL 容器复制裸指针或 shared_ptr 元素也存在类似的“指向同一个对象”语义。

QObject 本身不能像 QString 一样进行值复制。不要把隐式共享与 QObject 父子所有权、shared_ptr 共享所有权混为一谈。

隐式共享不是自动线程安全

不同线程操作各自的值副本，与多个线程同时读写同一个容器对象，是不同情况。引用计数机制不能代替后者所需的同步。

在项目中的用法

项目布局算法经常复制一组矩形，再计算调整后的结果。只读时共享可以减少复制；真正修改后，两份布局仍互不影响。

项目媒体层仍需要 mutex、condition_variable 和明确的只读帧契约，不能因为外面用了 Qt 类型就省掉线程协调。

Qt 容器与 STL 在项目中分别承担以下任务：

QJsonObject / QJsonArray / QJsonDocument

类型 负责什么
QJsonObject 表示 JSON 的花括号对象 {}
QJsonArray 表示 JSON 的方括号数组 []
QJsonDocument 将对象或数组解析自 JSON 字节，或序列化为 JSON 字节

QVariantMap 与 QJsonObject 不同：前者可以保存许多 Qt 或注册的 C++ 类型，后者受 JSON 的字符串、数字、布尔、数组、对象、null 等格式约束。QVariant 是程序内部的通用值，JSON 是序列化格式。

标准库本身没有对应的完整 JSON 解析器，使用 STL 的项目通常另外引入 JSON 库。

QDateTime / QElapsedTimer

QDateTime 回答“什么时候”

用途大致对应 std::chrono::system_clock 的时间点，但 QDateTime 还提供日期、格式化、时区等 Qt 接口。涉及跨时区或 UTC 数据时，要确保双方时间含义一致。

QElapsedTimer 回答“经过多久”

Qt 6.8 的 QElapsedTimer 使用单调时钟，接近 std::chrono::steady_clock，不会因手动调整系统日历时间而跳变

QElapsedTimer 不会自己周期触发回调，周期事件是 QTimer 的职责。这里 QTimer 决定何时统计，QElapsedTimer 测量真实经过的时长。

qint64 / quint64 / qsizetype

Qt 类型 标准类型的近似对应 关键点
qint64 std::int64_t 有符号，64 位
quint64 std::uint64_t 无符号，64 位
qsizetype 用途接近 std::ptrdiff_t 有符号尺寸类型，位宽随平台

qsizetype 与 size_t 不完全一样，size_t 是无符号的。混合有符号和无符号值进行比较、减法时，要留意转换结果。

QPointer

观察 QObject，对象销毁后自动清空
QPointer 不拥有对象，只观察 QObject 派生对象是否仍然存在。

普通裸指针在 delete 后通常仍保留旧地址，成为悬空指针；QPointer 会在 QObject 销毁时被清空。

类型 是否拥有对象 失效/释放方式
T* 类型本身不表达所有权 对象销毁后可能悬空
QPointer 不拥有，只适用于 QObject 派生类 QObject 销毁后自动清空
std::unique_ptr 独占所有权 拥有者释放对象
std::shared_ptr 共享所有权 最后一个拥有者释放对象
std::weak_ptr 不拥有，观察 shared_ptr 管理的对象 用 lock() 尝试取得临时共享所有权

QPointer 不是跨线程寿命锁，不能认为“检查非空后，对象就绝不会在另一线程销毁”。它也不同于 shared_ptr，不提供临时保活的 lock()。
