MVC 对比 MVVM 架构

MVC 中让 View 直接监听 Model 信号，并显示；Controller 负责业务逻辑并修改 Model。整体解耦，虽然 MV 仍有一定耦合，但分开了数据、显示与操作处理，明确了依赖边界。

MVVM 中 ViewModel 处理 Model 数据，让 View 显示（双向绑定），为界面提供了专门的状态与操作入口，使展示规则可以脱离具体窗口测试。

要解决的问题 MVC 风格 MVVM 风格
原始计数存在哪 Model Model
用户点击交给谁 Controller ViewModel 的操作方法
View 从哪里读数据 直接读 Model 读 ViewModel
显示文字由谁组织 可放在 View ViewModel
按钮可用等界面状态 View 判断，或由 Controller 协调 通常作为 ViewModel 属性提供

QWidget＋MVC 通常由 Controller 处理操作，View 监听 Model 后手动更新控件。QML＋MVVM 则通过 ViewModel 提供展示属性和操作入口，借助 QML 属性绑定更新界面。
对状态复杂的界面，MVVM 能集中展示规则，减少控件状态同步代码，也更便于测试；对于已有的 QWidget 项目，MVC 配合清晰的信号槽同样适用。都可以分离职责，解耦前后端。

两种方式都会响应变化，差别不是“一个自动、一个完全不自动”。 QWidget 的槽也会自动触发；QML 进一步替你管理了“读取依赖属性，并更新界面属性”这一步。

补充：Qt 的 Model/View/Delegate 与 MVC 有什么区别

前面的 MVC、MVVM 用来讨论界面与业务代码如何组织。
Qt Widgets 的 Model/View/Delegate 主要用于列表、表格、树形控件的数据展示与编辑：

  • Model：提供数据访问接口。
  • View：管理列表、表格或树的整体展示，以及选中、滚动等交互。
  • Delegate：负责单个数据项怎样绘制，以及编辑时使用什么编辑器。
    Qt 将传统 MVC 的 View 与部分 Controller 职责合到 View 中，再通过 Delegate 定制数据项的显示和编辑。

例如表格里有一个“年龄”单元格：

角色 做什么
Model 提供年龄 18，接受修改后的年龄
View 确定这一格的位置，处理选中和开始编辑
Delegate 平时绘制 18，编辑时提供数字输入框，提交新值

Delegate 不是改名后的 Controller。 它专门处理数据项的绘制和编辑，不负责整个应用的登录、设备连接等业务流程。
